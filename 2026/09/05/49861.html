1. 官网与安装包下载

  • 官方文档首页：https://docs.comfy.org （中文版 https://docs.comfy.org/zh/ ）
  • GitHub 源码：https://github.com/comfyanonymous/ComfyUI
  • Release 安装包（Windows 便携版等）：https://github.com/comfyanonymous/ComfyUI/releases

三种安装方式怎么选

  • Windows + NVIDIA 新手：用 ComfyUI Desktop（官网下载一键安装）或 Windows Portable（解压后双击 run_nvidia_gpu.bat）

  • macOS Apple Silicon：用 ComfyUI Desktop macOS 版

  • Linux / 开发者 / 要更新到最新 commit

    ：手动安装

    git clone https://github.com/comfyanonymous/ComfyUI.git
cd ComfyUI
python -m venv venv && source venv/bin/activate   # 或 conda
pip install -r requirements.txt
python main.py

    启动后浏览器开 

    http://127.0.0.1:8188

2. 模型下载与存放位置

ComfyUI 不自带模型，要把文件按类型丢进 ComfyUI/models/ 下对应子目录：

模型类型 目录 例子
主模型 Checkpoint（SD1.5/SDXL/FLUX） models/checkpoints/ sd_xl_base_1.0.safetensors
VAE models/vae/ sdxl_vae.safetensors
LoRA models/loras/ xxx.safetensors
ControlNet models/controlnet/ control_v11p_sd15_canny.safetensors
Upscale 超分 models/upscale_models/ 4x-UltraSharp.pth
CLIP / T5 文本编码器 models/clip/ 或随 checkpoint 自带 —
IPAdapter / CLIP-Vision models/ipadapter/、models/clip_vision/ —

模型去哪下：

  • HuggingFace（stabilityai、Comfy-Org 等组织）
  • CivitAI（需 token）
  • 官方文档里的 Model installation 章节也有直链示例

小技巧：在 ComfyUI/extra_model_paths.yaml 里可以把 A1111 / Forge 的模型目录挂过来，避免重复占盘。

3. 工作流里各模型/节点部分的作用（以基础文生图为例）

先记 5 种核心数据流（看连线颜色就懂）

  • MODEL（紫）：扩散主干（UNet / DiT），负责预测噪声
  • CLIP / CONDITIONING（黄→绿）：文本编码器，把 prompt 变成条件向量
  • VAE（红）：潜空间 ↔ 像素空间 互转
  • LATENT（蓝）：潜变量（文生图是单张噪声图；视频是 4D 张量：帧×通道×H×W）
  • IMAGE / VIDEO（白）：最终像素图或帧序列

视频和图片的本质区别：LATENT 从 2D 变成带时间维的 3D/4D，采样器内部走 DiT 时序注意力，末尾用视频 VAE 解码成帧再用 VHS_VideoCombine 封装 MP4

文生图（T2I，SD1.5 / SDXL / FLUX）

最基础的 6 节点直线：

CheckpointLoaderSimple
  ├─MODEL→ KSampler ← positive/negative(CLIPTextEncode)
  ├─CLIP ─→ CLIPTextEncode ×2
  └─VAE ──→ VAE Decode ← KSampler.LATENT
EmptyLatentImage → KSampler.latent_image
VAEDecode → SaveImage

各节点职责

  • CheckpointLoaderSimple：一个文件吐出 MODEL+CLIP+VAE 三件套（FLUX 等新模型会拆成 UNETLoader + DualCLIPLoader + VAELoader）
  • CLIPTextEncode（正/负）：把 prompt 编码成 CONDITIONING，接 KSampler 的 positive/negative
  • EmptyLatentImage：造一块纯噪声潜空间，定尺寸和 batch（SD1.5 用 512 基准，SDXL 用 1024）
  • KSampler：核心去噪，参数 seed/steps/cfg/sampler/scheduler/denoise 都在这
  • VAEDecode：潜空间 → 像素
  • SaveImage / PreviewImage：落盘或预览

图生图（I2I）

在文生图基础上把 EmptyLatentImage 换成：
LoadImage → VAEEncode → LATENT ─┐
├→ KSampler（denoise 0.40.7）
（其余同文生图） ┘
VAEEncode：把已有图片编码回潜空间，所以 KSampler 是在「原图潜变量+噪声」上继续去噪
denoise 是关键：1.0 等于文生图，0.0 原图不动，一般 0.40.6 做重绘/风格化

  1. 文生视频（T2V，Wan2.2 / HunyuanVideo / LTX-Video）
    以 Wan2.2 14B T2V 官方模板为例：
    Load Diffusion Model (high_noise_14B) ┐
    Load Diffusion Model (low_noise_14B) ├→ Wan 双专家 DiT 合并进 MODEL
                                    │
    Load CLIP (umt5_xxl) → CLIPTextEncode ×2（正/负）
    Load VAE (wan_2.1_vae)
    EmptyHunyuanLatentVideo（定 720p×帧数×fps）→ LATENT
     ↓
    KSampler（或 Wan 专用采样节点，steps 20~30）
     ↓
    VAEDecode（视频 VAE，输出帧序列 IMAGE）
     ↓
    VHS_VideoCombine → 存 MP4
    视频专属节点干什么
    Load Diffusion Model ×2：Wan2.2 是 MoE，高噪/低噪两个专家模型分别加载再合并；HunyuanVideo 则是 UNETLoader 单个 DiT
    Load CLIP = umt5_xxl / DualCLIP（CLIP+Llama）：视频模型文本编码器比图文模型大得多，放 models/text_encoders/
    EmptyHunyuanLatentVideo / LTXVModelConfigurator：造「视频潜空间」，参数含 width/height/frame_count/fps（LTX 要求帧数 = 8n+1，如 65/257）
    VAEDecode：视频 VAE 一次解出多帧
    VHS_VideoCombine（VideoHelperSuite 插件）：把帧序列按 fps 封装成 mp4/gif
    LTX-Video 2B 流程类似，但用 LTXVLoader + LTXVCLIPModelLoader + LTXVModelConfigurator + CFGGuider + SamplerCustomAdvanced 这套原生节点

图生视频（I2V）

在 T2V 基础上：多一个 LoadImage 作为首帧条件，潜空间不再是 Empty，而是由图构造。
Wan2.2 I2V 官方链路：
LoadImage(首帧) ─→ WanImageToVideo / Wan22ImageToVideoLatent
↓ 产出带首帧约束的 VIDEO LATENT
Load Diffusion Model(high/low noise I2V 版) → MODEL
CLIPTextEncode(运动描述 prompt) → positive/negative
↓
KSampler
↓
VAEDecode → VHS_VideoCombine → MP4
I2V 必须用 I2V 专用权重（wan2.2_i2v_high/low_noise_14B），不能用 T2V 权重
首帧通过 WanImageToVideo 节点注入潜空间，后续帧由 DiT 基于文本+首帧生成
提示词重点写「怎么动」（camera pan / blink / wind blows hair），CFG 比 T2V 略低（3~5）保住原图一致性
AnimateDiff 系 I2V（SD1.5 时代方案）：
Load Checkpoint → MODEL
ADE_AnimateDiffLoaderWithContext（挂运动模块+context 窗口）
LoadImage → VAEEncode → 首帧 latent 拼进 batch
KSampler → VAEDecode → VHS_VideoCombine
AnimateDiff 是给 SD 图像模型「打时序补丁」，不是原生视频 DiT，画质和运动幅度弱于 Wan/LTX，但 8G 显存能跑。

首尾帧生视频（FLF2V，Wan2.2 支持）

LoadImage(起点) ─┐
LoadImage(终点) ─┼→ WanFirstLastFrameToVideo → LATENT
                 │
T2V 双专家 MODEL + CLIP + VAE（同 T2V）
                 ↓
              KSampler → VAEDecode → VHS_VideoCombine

中间帧由模型在「首帧→尾帧」之间插值生成，适合转场/定格动画。

跨任务通用「加料」节点（不改变主干，只改条件）

这些节点在四种任务里都能插，作用位置固定：

插件节点 插在哪 干什么
LoraLoader Checkpoint 之后、KSampler 前 给 MODEL 打风格/角色 LoRA
ControlNetLoader + ApplyControlNet CLIPTextEncode 后，进 KSampler 前 用 canny/depth/pose 图约束构图（图生图/视频都可用）
IPAdapter + CLIPVisionLoader 接参考图，输出 CONDITIONING 合并进 KSampler 偷脸/偷风格，视频里保人物一致
UpscaleModelLoader + ImageUpscale VAEDecode 之后 单图超分；视频则逐帧或后期 Topaz
RIFE / GIMM-VFI 视频帧序列后、VideoCombine 前 帧率翻倍插值
AnimateDiff Uniform Context 仅 AnimateDiff 视频 控制滑动窗口长度保时序连贯

一句话归纳各「模型加载节点」的角色

  • CheckpointLoaderSimple / UNETLoader：拿扩散主干（图片 UNet 或视频 DiT）
  • DualCLIPLoader / CLIPLoader / LTXVCLIPModelLoader：拿文本编码器（小模型用 CLIP，视频用 umt5/llama/pixart）
  • VAELoader：拿图片 VAE；视频模型用自带视频 VAE（如 wan_2.1_vae）
  • LoRA / ControlNet / IPAdapter：附加权重，不改主干只改条件
  • EmptyLatentImage / EmptyHunyuanLatentVideo：造潜空间容器（图是 2D 噪声，视频是 3D 噪声块）
  • KSampler（或 Wan/LTX 专用采样节点）：去噪核心
  • VAEDecode → SaveImage / VHS_VideoCombine：潜空间落地为图或视频

默认文生图工作流是一条直线，节点职责如下：

  1. CheckpointLoaderSimple（加载检查点）

    读 checkpoints/ 里的主模型，一次性输出三个东西：

    • MODEL（扩散主干）
    • CLIP（文本编码器）
    • VAE（解码器）

  2. CLIPTextEncode（正/负提示词）
    把正面 prompt / 负面 prompt 文本，用上一步的 CLIP 编码成条件向量，分别接给 KSampler 的 positive / negative。

  3. EmptyLatentImage（空潜变量）
    定生成尺寸（如 512×512 给 SD1.5，1024×1024 给 SDXL）和 batch_size，产生纯噪声潜空间。

  4. KSampler（采样器）
    扩散核心。输入 model + positive + negative + latent_image，参数含 steps / cfg / sampler_name / scheduler / seed / denoise，输出降噪后的 latent。

  5. VAEDecode
    把 latent 用 VAE 解码回像素图。

  6. SaveImage
    存到 ComfyUI/output/，并且把整张工作流写进 PNG 元数据（别人把图拖进来可还原流程）。

图生图只是把 EmptyLatentImage 换成 LoadImage + VAEEncode；ControlNet 是再插一个 ControlNetLoader + ApplyControlNet 到 KSampler 前；LoRA 是 LoraLoader 插在 Checkpoint 之后。模型类节点负责“提供权重”，Sampler 类节点负责“算图”，VAE 类负责“潜↔像素”。

4. Python 脚本调用工作流 API

ComfyUI 的 Web 界面背后就是 HTTP 服务，核心端点：

  • POST /prompt 提交工作流（body 是 {"prompt": <API格式JSON>, "client_id": "可选uuid"}）
  • GET /history/{prompt_id} 轮询结果
  • WS ws://127.0.0.1:8188/ws?clientId=xxx 收实时进度
  • GET /view?filename=xxx 下载生成图

第一步：导出 API 格式 JSON

在 Web 界面：**Workflows → Export (API Format)**，存成 workflow_api.json。

注意：不是普通“保存”得到的 UI JSON（带坐标那种），API 格式是 { "3": {"class_type":"KSampler","inputs":{...}}, ... } 这种扁平结构。

第二步：最小 Python 提交脚本（火忘式）

import json, urllib.request

SERVER = "127.0.0.1:8188"

def queue_prompt(prompt):
    body = json.dumps({"prompt": prompt}).encode()
    req = urllib.request.Request(f"http://{SERVER}/prompt", data=body)
    return json.loads(urllib.request.urlopen(req).read())

with open("workflow_api.json") as f:
    wf = json.load(f)

# 动态改参：节点 ID 看你导出的 JSON 实际是多少
wf["6"]["inputs"]["text"] = "masterpiece, a fox in snow, cinematic"
wf["3"]["inputs"]["seed"] = 12345

resp = queue_prompt(wf)
print("prompt_id:", resp["prompt_id"])

跑完图会写在服务端 output/，脚本不自动拿图。

第三步：推荐写法——WebSocket 等完成再下载

import json, uuid, urllib.request, urllib.parse, websocket  # pip install websocket-client

SERVER = "127.0.0.1:8188"
client_id = str(uuid.uuid4())

def queue(prompt, pid):
    body = json.dumps({"prompt": prompt, "client_id": client_id, "prompt_id": pid}).encode()
    urllib.request.urlopen(urllib.request.Request(f"http://{SERVER}/prompt", data=body))

def get_image(fn, sub, t):
    q = urllib.parse.urlencode({"filename": fn, "subfolder": sub, "type": t})
    return urllib.request.urlopen(f"http://{SERVER}/view?{q}").read()

with open("workflow_api.json") as f:
    wf = json.load(f)
pid = str(uuid.uuid4())
queue(wf, pid)

ws = websocket.WebSocket()
ws.connect(f"ws://{SERVER}/ws?clientId={client_id}")
while True:
    msg = json.loads(ws.recv())
    if msg["type"] == "executing" and msg["data"]["node"] is None and msg["data"]["prompt_id"] == pid:
        break
ws.close()

hist = json.loads(urllib.request.urlopen(f"http://{SERVER}/history/{pid}").read())[pid]
for node_id, out in hist["outputs"].items():
    for img in out.get("images", []):
        data = get_image(img["filename"], img["subfolder"], img["type"])
        open(img["filename"], "wb").write(data)
        print("saved", img["filename"])

这就是官方 websockets_api_example.py 的精简版，生产环境直接用这个模式。

用 requests 也行，逻辑一样：POST /prompt → 拿 prompt_id → 轮询 /history/{id} → 从 outputs 里取 images 再 GET /view。

5. 新手最容易卡住的 3 个点

  • 模型不显示：放错子目录（LoRA 放成 checkpoint 就不会出现在 LoraLoader 里），或没点界面刷新。
  • API 提交报错：用的是“界面保存”的 JSON 而不是“Export (API Format)”；或者节点 ID 写死但你导出的图里 ID 不一样。
  • FLUX 等新模型：主模型可能走 diffusion_models/ + 单独 clip/t5xxl + vae，不是单个 checkpoint，工作流要用 UNETLoader / DualCLIPLoader 等节点，不能直接套 SD1.5 模板。

剪映（手机 App / 电脑专业版 / 网页版通用逻辑）做「拼接视频 + 生成文字 + 生成音频」最常用就是三条主线：多段拼接剪辑、语音/文案转字幕、文字转语音（AI 配音）。下面按你实际干活顺序给一套可照抄的流程。

一、多段视频拼接与基础剪辑

1. 新建与导入

  • 打开剪映 → 「开始创作」→ 相册里按播放顺序勾选多段视频/图片 → 添加进项目（顺序按你勾选顺序排，错了后面可拖）。
  • 电脑版：媒体库导入后，全选拖到 V1 主轨道，自动首尾相接。

2. 粗剪（掐头去尾、删废片）

  • 选中片段，拖两端白边裁长短；中间要删 → 移动播放头到切点 → 点「分割」（电脑 Ctrl/Cmd+B）→ 选多余段点删除。
  • 片段间别留缝，否则导出有黑帧；长按拖动可换顺序。

3. 转场（让切换不硬）

  • 点两段之间的「白色方块」→ 选叠化/淡入淡出/模糊，时长 0.3–0.5 秒最稳，别用花哨闪光。
  • 多段统一：右键「应用到全部转场」。

4. 统一画风

  • 「调节」里把亮度/对比度/色温按统一数值拉一遍，或套同一个滤镜，避免拼接后忽明忽暗。

5. 导出

  • 1080P 30fps（动作多的 60fps），MP4，码率「推荐/更高」，关掉「自动添加片尾」。

二、生成文字（字幕）：两种来源

方式 A：已有视频带人声 → 语音识别字幕

  1. 时间线放好视频（保留原声或先别关）
  2. 点「文本」→「识别字幕」/「智能字幕」→ 选语言（中/英/粤/川渝等）→「开始识别」
  3. 十几秒后字幕轨自动生成，双击改错字（普通话准确率 95%+）
  4. 批量改样式：选字幕 → 样式 → 白字黑描边、字号 28–32、底对齐，适合抖音竖屏

方式 B：已有文案/口播稿 → 直接建文本

  • 「文本」→「新建文本」粘贴文案 → 这层文本本身不是字幕轨，但可后续用「文本朗读」变成配音，再「识别字幕」反推时间轴字幕（见下节）。

还有个「文稿匹配」：把讲稿粘进去，系统按你原视频说话节奏自动对位，适合脚本固定的课件。

三、生成音频：文字转语音（AI 配音）与录音

方式 1：AI 文本朗读（最常用，不用自己录音）

  1. 「文本」→「新建文本」→ 输入或粘贴文案（长文建议每段 ≤500 字）
  2. 选中该文本层 → 点「文本朗读」/「AI 配音」
  3. 挑音色：知识解说用「沉稳男声/知性女声」，情感用「温柔女声」，搞笑用方言；语速 1.05–1.1 倍更跟手，开「智能停顿」像真人呼吸
  4. 生成后音频自动进音频轨，与原文本长度对齐
  5. 若只要配音不要那层静态文本：生成配音后删掉文本层，再对音频轨「识别字幕」出同步字幕

方式 2：自己录音

  • 「音频」→「录音」→ 红点录 → 停 → 对勾。适合要真人温度。
  • 录完有杂音：选中音频 →「降噪」；人声小：「音量」拉满，BGM 调到 10–15% 或开「自动闪避」。

方式 3：图文成片（懒人全自动）

  • 首页「图文成片」→ 粘一段文案 → AI 自动找素材画面 + 生成配音 + 套字幕，出一条粗剪片，再手动微调。适合资讯号日更。

四、一条标准「拼接 + 字幕 + 配音」成片顺序（推荐）

  1. 拼好视频主轨（分割删废片 + 0.3s 叠化）
  2. 先定音频：新建文本 → 文本朗读生成 AI 配音（此时配音长度决定成片节奏）
  3. 把画面片段按配音断句对齐（一句配音对应一段画面，或按踩点点切割）
  4. 关原声（如不需要现场声）→ 加 BGM（音量 < 人声）
  5. 对最终音频轨点「识别字幕」→ 改错字 → 套字幕样式
  6. 统一调色 → 1080P 导出

反向顺序（先剪画再配旁白）也行，但 AI 配音长度不可控，常要回头裁画面，新手更容易乱。
