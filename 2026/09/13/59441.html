ComfyUI启动参数配置

tool comfyui
tool
发布日期:   2026-09-13
文章字数:   3.2k
阅读时长:   13 分
阅读次数:  

ComfyUI 默认就是「优先占满 GPU 显存，不够自动卸载权重/激活到 CPU RAM」，你要做的是别开 --gpu-only，并配好动态卸载。

一、核心原理先搞清楚

  • GPU优先：模型加载、采样、attention 优先在 CUDA 执行。
  • 自动卸载：Dynamic VRAM 开启时，显存快满就把部分层/权重搬 RAM，用时搬回。
  • CPU兜底：--cpu-vae、--lowvram 让 VAE / 文本编码器常驻 CPU。
  • 不是无缝：卸载会掉速，但不会 OOM 崩；--gpu-only 才会纯显存、爆了就报错。

二、ComfyUI侧怎么配

1. 启动参数（改bat/json）

  • 12GB卡（你这种）：main.py --medvram --reserve-vram 1.5 --async-offload --cpu-vae。
  • 8–10GB卡：--lowvram --reserve-vram 1.5 --cpu-vae --fp16-unet。
  • 6GB↓：--lowvram --novram --reserve-vram 1 --cpu-vae --fp8_e4m3fn-unet。
  • 16GB+想快：--highvram（常驻显存，不自动卸）。
  • 千万别加：--gpu-only（禁止卸CPU，必爆）。
  • Wan视频专用：上面 --medvram 版再加 --fp8_e4m3fn-text-enc。

2. 便携版改法

  • 找脚本：ComfyUI 目录 run_nvidia_gpu.bat（秋叶/官方便携包）。
  • 改内容：原行 .\python_embeded\python.exe -s ComfyUI\main.py → 末尾加参。
  • 示例：...\python.exe -s ComfyUI\main.py --medvram --reserve-vram 1.5 --async-offload --cpu-vae。
  • 保存：存盘双击启动，nvidia-smi 看占用曲线。

3. 启动器/桌面版

  • ComfyUI-Desktop：Settings → Launch Flags 填 --medvram --reserve-vram 1.5 --cpu-vae。
  • pinokio/comfy-cli：comfy launch -- --medvram --reserve-vram 1.5。
  • comfy.settings.json：加 "vram_management": "medvram"（部分构建支持）。

4. 界面Settings辅助

  • VRAM management：选 Auto 或 Medium（别选 Full/GPU-only）。
  • Reserve VRAM：填 1.5。
  • Preview：None / Latent（别开 taesd）。
  • Cache：开 cache-lru 100 或 --cache-ram 6.0。

三、Win11系统侧怎么设

1. 绑定独显运行

  • 路径：设置 → 系统 → 显示 → 图形 → 添加桌面应用。
  • 选文件：选 ComfyUI\python_embeded\python.exe（或 run_nvidia_gpu.bat 不行就选 python.exe）。
  • 设首选：选项 → 高性能（独显），保存。
  • 笔记本必做：防核显偷跑。

2. 虚拟内存（CPU卸载的命根子）

  • 入口：此电脑→属性→高级系统设置→性能→高级→虚拟内存→更改。
  • 设置：取消自动管理；选 SSD 盘；自定义大小。
  • 参考值：16GB RAM→初始 24576 / 最大 65536 MB；32GB→16384 / 32768。
  • 生效：点设置→确定→重启PC。

3. 关硬件加速GPU调度

  • 路径：设置→系统→显示→图形→更改默认图形设置。
  • 操作：关「硬件加速 GPU 调度」。
  • 原因：Win11 HAGS 会多占 0.5–1GB 显存，小卡跑 Wan 建议关。

4. NVIDIA控制面板

  • 程序设置：添加 python.exe → 首选处理器「高性能 NVIDIA」。
  • 电源模式：最高性能优先。
  • 关项：图像缩放、DSR、低延迟模式设「关」。
  • 着色器缓存：开 10GB（模型重载快）。

5. 电源与后台

  • 电源计划：Win 电源→「最佳性能」/ 插电。
  • 关后台：Discord GPU 加速、浏览器硬件加速、Wallpaper Engine、OBS。
  • BIOS：独显机 UMA 共享显存设 64MB–256MB，别给 4GB+。

四、直接抄作业配置

1. 启动bat示例

@echo off
cd /d D:\ComfyUI\ComfyUI-Installs\ComfyUI
.\python_embeded\python.exe -s ComfyUI\main.py ^
  --medvram ^
  --reserve-vram 1.5 ^
  --async-offload ^
  --cpu-vae ^
  --fp16-unet ^
  --preview-method none
pause

2. Win11动作清单

  • 图形设置绑 python.exe=高性能。
  • 虚拟内存 SSD 24–64GB，重启。
  • 关 HAGS。
  • N卡面板：高性能+最高性能电源。
  • 关 Discord/浏览器 GPU 加速。

3. 验证是否生效

  • 启动看日志：DynamicVRAM enabled / medvram mode。
  • nvidia-smi：采样时显存到 ~10–11GB 后不报 OOM，RAM 占用涨→说明卸到 CPU。
  • 跑原 Wan 工作流：帧数≤16、480P，不崩即成功。

五、常见误区

  • 「设个开关让显存不够自动用CPU算」：ComfyUI 是卸载权重到 RAM，计算仍在 GPU；真·全 CPU 只有 --cpu（极慢）。
  • 开 --gpu-only 再指望卸CPU：矛盾，必 OOM。
  • Win 共享显存=免费显存：那是核显/UMA 概念，独显 OOM 不靠系统共享救。
  • 虚拟内存设太小：低显存跑 Wan + --cpu-vae，RAM 爆会转页面文件，太小直接卡死。
  • HAGS 开着更顺：小显存反向，关了省显存。

按上面 bat + Win11 四项设完，就是「GPU 优先、爆了自动卸 RAM、VAE 走 CPU」的最稳态。要我按你具体显卡（如 3060 12G / 4070 12G）微调 --reserve-vram 数值吗？

你这张图是 RTX 5070 Ti Laptop GPU，专用显存 12GB，系统内存 32GB，Windows 显示共享 GPU 内存上限 15.9GB。当前专用显存用了 7.8/12GB，共享 0.1/15.9GB，这是正常的。

1）任务管理器里这三项分别是什么

  • 专用 GPU 内存 = 真正显存 VRAM
    你这张卡是 12GB GDDR/GDDR7 显存，带宽很高，GPU 直接访问最快。
  • 共享 GPU 内存 = Windows 从系统 RAM 划出来可给 GPU 借用的额度
    通常不是真占用了，而是“上限/可借额度”。你 32GB 内存，Windows 大约按一半显示可用共享 GPU 内存，所以显示 15.9GB。
    它不是额外硬件显存，速度走系统内存 + PCIe，远慢于专用显存。
  • GPU 内存 = 专用 + 共享的合计显示值
    你这里 7.9/27.9GB 是统计口径合计，不代表真有 28GB 高速显存。

底层机制在 CUDA 侧叫 Unified Memory / 可迁移内存（Pascal 及以后支持页面迁移、显存超额订阅）；在 Windows 侧是 WDDM 管理的共享内存/溢出机制。正常优先用 VRAM，压力/映射需要时才会走系统内存。

2）ComfyUI/PyTorch/CUDA 怎么用“共享 GPU 内存”

要分清两个概念：

A. ComfyUI 主动 CPU offload

你加 --medvram / --lowvram / --cpu-vae / --async-offload 时，ComfyUI/PyTorch 是把模型权重/激活/VAE 放到 CPU RAM，计算前再搬回 GPU。任务管理器里通常不一定表现为“共享 GPU 内存”上涨，而是系统内存/RAM 和 PCIe 拷贝活动增加，GPU 专用显存下降或波动。

B. CUDA/Windows 透明走共享内存/统一内存

当 CUDA 分配或访问触发 Unified Memory / WDDM 共享表面时，数据可能在系统内存里，GPU 通过 PCIe 按需访问/迁移。比如某些 CUDA 分配、图形互操作、页面迁移、显存压力兜底时会用到。任务管理器“共享 GPU 内存”才会动。

但 PyTorch/ComfyUI 正常训练/推理路径一般更倾向：

尽量 cudaMalloc 在 VRAM；不够就报错 OOM，或靠 ComfyUI 自己的 CPU offload/模型搬移。不是简单“专用显存满了就自动安静转共享跑”，否则会极慢且容易卡/崩。

你当前 7.8/12GB，离满还远，所以共享几乎不用，完全正常。

3）哪些场景会用到共享 GPU 内存

常见场景：

  1. 显存真的快满/某些分配走统一内存或 WDDM 共享资源
    例如大分辨率、视频模型 Wan/AnimateDiff、FLUX fp16、多 ControlNet/IPAdapter/LoRA、预览/TAESD、图形队列等。
  2. Windows 桌面/合成/浏览器硬件加速/DirectX 表面共享
    窗口、浏览器、视频播放、WSL/GPU 调度等可能走共享内存路径。
  3. CUDA Unified Memory 迁移/溢出场景
    程序显式或运行时走 managed memory，或某些扩展/插件内部分配路径。
  4. 核显/混合显卡场景更明显
    但你这是独显笔记本 GPU，共享只是兜底，不是主算力内存。
  5. 某些视频编解码/预览/显示相关资源
    你图里 Video Encode/Decode 0%，说明当前没走硬编解码。

对 ComfyUI 来说，更常见的“省显存”是：模型放 CPU RAM、VAE 放 CPU、分层 offload、FP8/FP16、Tiled VAE/注意力/TEACache/WaveSpeed 等，不是依赖任务管理器那个共享 GPU 内存。

4）你这张卡建议怎么跑 ComfyUI

RTX 5070 Ti Laptop 12GB + 32GB RAM，挺强。一般不必刻意追求共享内存。

  • 普通 SDXL/FLUX fp8：可不加或轻量

    python main.py --fp8_e4m3fn-unet --fp8_e4m3fn-text-enc

    或默认/ 

    --highvram

    如果只想常驻更快；但跑重工作流建议：

    python main.py --medvram --reserve-vram 1.2 --cpu-vae --async-offload

  • Wan 视频/高帧高分辨率：

    python main.py --medvram --reserve-vram 1.5 --cpu-vae --async-offload --fp8_e4m3fn-unet --fp8_e4m3fn-text-enc

    配合 WaveSpeed/TeaCache、Tiled VAE、低帧数/480P~720P。

  • 不要加 --gpu-only，否则不自动卸 CPU，显存不够直接 OOM。

Win11 侧：虚拟内存保持足够，比如 16–32GB 页面文件；图形设置里 python.exe 高性能；HAGS 可按稳定性选择，跑 AI 有时关更稳。

5）重点结论

  • 共享 GPU 内存不是“可扩展显存”，是 系统 RAM 给 GPU 的兜底/共享额度，慢很多。
  • 你现在 7.8/12GB 专用，没用共享是正常的。
  • ComfyUI 省显存主要靠 CPU offload/精度/分块/FP8/Tiled/节点策略，不是靠 Windows 共享 GPU 内存。
  • 只有接近/触发 CUDA 内存压力、统一内存/图形共享/某些分配路径时，共享才会明显被用。

ComfyUI 参数加在 python main.py 或 run_nvidia_gpu.bat 后面。官方源码以 comfy/cli_args.py 为准。

一、显存与内存管理

1. 显存模式切换

  • **--gpu-only**：CLIP/文本编码器/VAE/UNet 全留 GPU，不卸 CPU；≥24GB 才用。
  • **--highvram**：用后不卸载模型，常驻显存；12–24GB 多轮出图快。
  • **--normalvram**：强制默认平衡模式，覆盖自动 lowvram。
  • **--medvram**：中等卸载，分层搬 CPU↔GPU；6–12GB 常用。
  • **--lowvram**：UNet 分块执行，文本编码器走 CPU；4–8GB。
  • **--novram**：比 lowvram 更激进，权重基本在 CPU；2–4GB 救急。
  • **--cpu**：全 CPU 推理，无 GPU 时用，极慢。

2. 精细显存控制

  • **--reserve-vram 1.5**：给 Win 桌面/驱动留 1.5GB，不超物理显存。
  • **--vram-headroom 1**：DynamicVRAM 额外空出 1GB 不用。
  • **--async-offload [N]**：N 条 CUDA 流异步搬权重（N卡默认2）。
  • **--disable-async-offload**：关异步，回退同步。
  • **--disable-dynamic-vram**：关动态管理，回退估算加载。
  • **--enable-dynamic-vram**：非默认平台强开动态 VRAM。
  • **--disable-smart-memory**：不缓存模型层，用就搬走，稳但慢。
  • **--disable-pinned-memory**：关锁页内存，部分 APU/老卡避坑。

二、精度与数据类型

1. 全局强制

  • **--force-fp32**：全模型 FP32，最稳最费显存。
  • **--force-fp16**：全模型 FP16，老卡黑图时别用。

2. UNet/扩散模型

  • **--fp32-unet / --fp64-unet**：高精度，慢，调试用。
  • **--fp16-unet**：半精度，8–16GB 常用。
  • **--bf16-unet**：Ampere+ 推荐，比 fp16 不易溢出。
  • **--fp8_e4m3fn-unet**：FP8 权重，显存骤降；需 SM89+（40/30系）。
  • **--fp8_e5m2-unet / --fp8_e8m0fnu-unet**：其他 FP8 变体。

3. VAE 相关

  • **--cpu-vae**：VAE 解码放 CPU，降显存峰值首选。
  • **--fp16-vae**：省显存，部分模型黑图。
  • **--fp32-vae**：默认，最稳。
  • **--bf16-vae**：N卡 Ampere+ 平衡选。

4. 文本编码器

  • **--fp8_e4m3fn-text-enc**：CLIP/T5 量化，Wan/FLUX 省显存。
  • **--fp16-text-enc / --bf16-text-enc / --fp32-text-enc**：手动指定精度。

5. 注意力精度

  • **--force-upcast-attention**：修黑图/噪点。
  • **--dont-upcast-attention**：禁升位，省显存但易翻车。

三、注意力与计算加速

  • **--use-pytorch-cross-attention**：PyTorch SDPA，现代卡默认推荐。
  • **--use-sage-attention**：SageAttention，需装包，快且省。
  • **--use-flash-attention**：FlashAttn，兼容时最快。
  • **--use-split-cross-attention**：老卡/无 xformers 兜底。
  • **--use-quad-cross-attention**：子二次注意力，省显存。
  • **--disable-xformers**：冲突时禁用。
  • **--force-channels-last**：NHWC 布局，张量核利用率高。
  • **--fast [opt]**：实验优化（fp16_accumulation/fp8_matrix_mult）。
  • **--cuda-malloc / --disable-cuda-malloc**：切 cudaMallocAsync。

四、缓存与执行策略

  • **--cache-lru N**：缓存最近 N 个节点结果，吃 RAM 省重算。
  • **--cache-classic**：旧版激进缓存。
  • **--cache-none**：不缓存，最省内存。
  • **--cache-ram 6.0**：限制 RAM 缓存上限 GB。
  • **--preview-method none|auto|latent2rgb|taesd**：出图预览，none 最省。
  • **--preview-size 512**：预览图最大边。
  • **--deterministic**：可复现但慢。
  • **--high-ram**：大内存时禁 RAM 限制。

五、网络与服务访问

  • **--listen [IP]**：不填=0.0.0.0，填IP限绑；局域网/API 用。
  • **--port 8188**：改端口。
  • **--tls-keyfile + --tls-certfile**：启用 HTTPS。
  • **--enable-cors-header [\*]**：API 跨域。
  • **--max-upload-size 500**：上传模型/图上限 MB。
  • **--auto-launch / --disable-auto-launch**：开/禁自动开浏览器。
  • **--multi-user**：按用户隔离存储。

六、路径与多设备

  • **--base-directory D:**：重定位 models/custom_nodes/output。
  • **--extra-model-paths-config a.yaml**：挂额外模型盘。
  • **--output-directory / --input-directory / --temp-directory**：分目录覆盖。
  • **--user-directory**：多用户配置隔离。
  • **--cuda-device 1**：多卡指定第2张。
  • **--directml [id]**：AMD/Intel 走 DirectML。
  • **--oneapi-device-selector**：Intel XPU。

七、调试与其他杂项

  • **--disable-all-custom-nodes**：排错节点冲突。
  • **--disable-metadata**：出图不写 prompt 元数据。
  • **--verbose DEBUG**：日志级别。
  • **--default-hashing-function sha256**：模型去重哈希。
  • **--front-end-version owner/repo@ver**：切前端版本。
  • **--windows-standalone-build**：便携版开便捷特性。
  • **--mmap-torch-files / --disable-mmap**：控制模型映射加载。

八、按显卡抄作业

  • 2–4GB（MX/Mobile）：--novram --cpu-vae --preview-method none --reserve-vram 0.8（仅小图）。
  • 6–8GB（3060 6G）：--lowvram --reserve-vram 1 --cpu-vae --fp16-unet。
  • 12GB（3060/4070）：--medvram --reserve-vram 1.5 --async-offload --cpu-vae（Wan 加 --fp8_e4m3fn-unet --fp8_e4m3fn-text-enc）。
  • 16–24GB：--highvram --fp16-unet --preview-method taesd。
  • **24GB+**：--gpu-only --fast。
  • 无独显/纯 CPU：--cpu --preview-method none --cache-lru 50。

九、改参实操与避坑

1. 便携版改法

编辑 run_nvidia_gpu.bat：python.exe -s ComfyUI\main.py --medvram --reserve-vram 1.5 --cpu-vae。

2. 手动版

python main.py --lowvram --cpu-vae --reserve-vram 1。

3. comfy-cli

comfy launch -- --medvram --reserve-vram 1.5。

4. 常见避坑

  • 显存模式只选一个，别 --highvram --lowvram 同开。
  • --reserve-vram 别大于物理显存×70%。
  • FP8 老卡（10系/16系）不支持会报 kernel 错。
  • --fast 可能降质，生产别开。
  • 改完重启 ComfyUI，看启动日志确认 DynamicVRAM/medvram 生效。
