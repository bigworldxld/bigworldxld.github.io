远程使用本地AI工具

LLM tool cc-connect feishu
tool
发布日期:   2026-10-18
文章字数:   1.9k
阅读时长:   8 分
阅读次数:  

cc-connect（chenhg5/cc-connect）：把本地 Claude Code / Codex / Cursor / Gemini CLI 等 Agent 桥接到飞书、Telegram、钉钉等聊天软件。

下面按「安装 → 环境 → 飞书 → 模型/Provider → 使用」走一遍。

一、安装 cc-connect

GitHub：https://github.com/chenhg5/cc-connect

方式 1：npm（最常用）

node -v        # 需要 Node.js 18+
npm install -g cc-connect
cc-connect --version

方式 2：Homebrew（macOS / Linux）

brew install cc-connect

方式 3：二进制

去 Releases 下载 cc-connect-linux-amd64 / darwin-arm64 / windows-amd64，放进 PATH：

curl -L -o cc-connect https://github.com/chenhg5/cc-connect/releases/latest/download/cc-connect-linux-amd64
chmod +x cc-connect
sudo mv cc-connect /usr/local/bin/

方式 4：源码编译

git clone https://github.com/chenhg5/cc-connect.git
cd cc-connect
make build

二、本机环境准备

cc-connect 本身不“代替” Claude Code，它是桥：

  • Node.js 18+
  • 本地已安装并登录目标 Agent：
    • Claude Code：claude 命令可用
    • Codex / Gemini / Cursor / OpenCode 同理
  • 电脑保持开机、联网
  • 飞书 App 已登录

Claude Code 示例：

claude --version

三、飞书环境配置

1. 飞书开放平台建应用

地址：https://open.feishu.cn → 开发者后台 → 创建企业自建应用

要做的事：

  1. 应用能力 → 开启「机器人」

  2. 凭证与基础信息

    → 记好：

    • App ID（如 cli_xxx）
    • App Secret

  3. 权限管理

    开通：

    • im:message
    • im:message:send_as_bot
    • im:message:receive_v1
    • im:resource（收图片/文件）

  4. 事件与回调 → 事件订阅

    • 连接方式：长连接（不用公网 IP）
    • 订阅事件：im.message.receive_v1
    • 如果用了交互卡片，还要订阅 card.action.trigger

  5. 版本管理与发布 → 创建版本 → 发布/申请上线（企业自建通常很快生效）

⚠️ 一个飞书 App 对应一个长连接；多项目建议多建飞书应用，或用 /bind 多群隔离。

2. cc-connect 配置文件

配置目录：

~/.cc-connect/config.toml

最小可用配置（Claude Code + 飞书）：

language = "zh"

[log]
level = "info"

[[projects]]
name = "my-project"
admin_from = "ou_你的飞书open_id"

[projects.agent]
type = "claudecode"

[projects.agent.options]
work_dir = "/Users/yourname/code/my-project"
mode = "default"   # default / auto / acceptEdits / plan / bypassPermissions

[[projects.platforms]]
type = "feishu"

[projects.platforms.options]
app_id = "cli_xxxxxxxx"
app_secret = "xxxxxxxx"
allow_from = "ou_你的飞书open_id"

也可以走命令行初始化：

cc-connect feishu setup --project my-project

会引导你建/绑飞书机器人并写回配置。

3. 获取你自己的飞书 open_id

启动后给机器人发：

/whoami

返回里的 open_id 填到 admin_from / allow_from。

注意：Bot 自己的 open_id 不是你的；open_id 是 per-app 的。

四、模型 / Provider 配置

cc-connect 的 claudecode agent 默认用你本机 Claude Code 的登录态和模型。

1. 直接用 Claude Code 原生命模型

本地设置：

claude config set model claude-opus-4
claude config set model claude-sonnet-4

飞书里发：

/model

可看/切模型（取决于本地 Claude Code 版本）。

2. 用自定义 API Provider（中转/OpenAI 兼容）

cc-connect provider add \
  --project my-project \
  --name myrelay \
  --api-key sk-xxxx \
  --base-url https://api.your-relay.com

聊天里：

/provider list
/provider switch myrelay
/model
/model gpt-4o

支持的多 Agent 类型：

type = "claudecode"
type = "codex"
type = "gemini"
type = "cursor"
type = "opencode"

五、启动 cc-connect

临时前台运行

cc-connect

Web 管理界面（新手友好）

cc-connect web

浏览器打开本地管理页，可视化建项目 / 配飞书 / 配 Provider。

守护进程 / 开机自启

cc-connect daemon install
cc-connect daemon start
cc-connect daemon status

# 改配置后
cc-connect daemon restart
cc-connect daemon logs -f

macOS / Linux 也可用 tmux：

tmux new-session -d -s cc-connect 'cc-connect'
tmux attach -t cc-connect

六、飞书里实际使用

给机器人发普通消息：

帮我看下 src/api/user.py 有没有安全漏洞

常用命令：

命令 作用
/new 名称 开新会话
/list 列会话
/switch <id> 切会话
/current 当前会话
/dir /path/to 切工作目录
/mode 看权限模式
/mode auto 自动执行
/mode default 每步确认
/mode bypassPermissions YOLO，慎用
/model 看模型
/model <name> 切模型
/provider list 看 Provider
/provider switch <name> 切 Provider
/memory 看 Agent 记忆
/cron add ... 自然语言定时任务
/whoami 看自己 open_id
/bind 项目名 群绑定项目

多项目做法：

  • 项目 A 群 → /bind my-project
  • 项目 B 群 → /bind another-project
  • 私聊机器人 → 默认第一个项目

七、常见坑

  1. 机器人不回消息
    → 没开「机器人」能力 / 没发 im.message.receive_v1 / 应用没发布
  2. 卡片报错 200340
    → 没订阅 card.action.trigger
  3. 谁都能控制你电脑
    → allow_from = "*" 很危险，改成自己的 ou_xxx
  4. 改了 config.toml 没生效
    → 必须 cc-connect daemon restart
  5. Claude 乱删文件
    → 别用 bypassPermissions 跑重要仓库

cc-connect 本身没有“关机按钮”，但它能让你在飞书里跑本地 shell，所以“远程关机”本质是：飞书 → cc-connect → 本地 Agent 执行关机命令。这很方便，但也等于把“关电脑/跑任意命令”的权限交给了能发消息的人，一定要限 admin_from。

下面分 macOS / Linux / Windows 三种。

实现远程关机

一、前提（很重要）

  1. cc-connect 已连飞书 ✅
  2. 项目配置里设置了 admin_from，只有你自己的飞书 open_id 能跑 /shell
  3. 电脑上 cc-connect 是常驻运行（daemon / tmux / launchd / systemd）
  4. 关机命令一旦执行，cc-connect 自己也会跟着死
[[projects]]
name = "home-pc"
admin_from = "ou_你的飞书open_id"   # 没有这行，/shell 很危险

[projects.agent]
type = "claudecode"

[projects.agent.options]
work_dir = "~/code"

[[projects.platforms]]
type = "feishu"

[projects.platforms.options]
app_id = "cli_xxx"
app_secret = "xxx"
allow_from = "ou_你的飞书open_id"

改完：

cc-connect daemon restart

飞书里先试特权命令是否可用：

/whoami
/shell echo ok

能回 ok 就说明 shell 通道通了。

二、飞书里直接关机（最省事）

macOS

/shell osascript -e 'tell app "System Events" to shut down'

或者：

/shell sudo shutdown -h now

macOS 上 shutdown 可能要授权；osascript 更稳，但首次会弹 macOS 辅助功能/Terminal 权限，要允许。

Linux

/shell systemctl poweroff

或：

/shell shutdown -h now

如果当前用户没权限：

echo "你的用户 ALL=(ALL) NOPASSWD: /sbin/shutdown, /bin/systemctl" | sudo tee /etc/sudoers.d/cc-shutdown

Windows（WSL 或 PowerShell 后端）

PowerShell：

/shell shutdown /s /t 0

WSL 里关 Windows：

/shell powershell.exe shutdown /s /t 0

三、更安全的做法：自定义“关机口令”

别让 Agent 自由发挥关机，做一个固定指令。

方案 A：让 Claude Code 只跑白名单脚本

本地建脚本：

macOS

mkdir -p ~/bin
cat > ~/bin/pc-shutdown <<'EOF'
#!/bin/bash
osascript -e 'tell app "System Events" to shut down'
EOF
chmod +x ~/bin/pc-shutdown

Linux

cat > ~/bin/pc-shutdown <<'EOF'
#!/bin/bash
systemctl poweroff
EOF
chmod +x ~/bin/pc-shutdown

飞书里发：

/shell ~/bin/pc-shutdown

你也可以让 Agent 这么用：

如果用户说“下班关机 / shutdown pc / 关电脑”，只允许执行 ~/bin/pc-shutdown，不许拼其他 shutdown 命令。

把这段写进项目 CLAUDE.md 或 memory，比裸发 /shell shutdown 安全得多。

四、用 /cron 做“定时关机”

/cron add 30 23 * * * ~/bin/pc-shutdown

意思：每天 23:30 关机。

查看：

/cron list

五、推荐：加二次确认

关机类操作别一句话就执行。两种思路：

  1. 不用 yolo

保持：

/mode default

Agent 执行 shell 会在飞书弹“允许/拒绝”卡片，你点允许才关。

  1. 关键字拦截

在 CLAUDE.md 写：

关机/重启/rm -rf/格式化 等危险操作：
- 必须先回复“确认关机？回复 确认关机 我再执行”
- 收到精确口令才调用 ~/bin/pc-shutdown
- 不允许拼接其他命令

飞书里流程：

你：关电脑
Bot：确认关机？回复「确认关机」
你：确认关机
Bot：执行 ~/bin/pc-shutdown

六、常见坑

  • daemon 用 launchd/systemd 跑，关机后不会自动回来

    ：下次开机要系统登录后自启

    • macOS：LaunchAgent + 登录自启
    • Linux：systemd user service + loginctl enable-linger 用户名

  • macOS 不关机：没给 Terminal/iTerm 辅助功能权限

  • Linux 没权限：shutdown 需要 root，配 NOPASSWD

  • 谁都能关你电脑：admin_from 没设，或 allow_from = "*"

  • Agent 自作主张关机：开了 /mode yolo 又说“晚上帮我收尾”

七、最小可用流程（总结）

  1. 配 admin_from = "ou_xxx"

  2. 本地建 ~/bin/pc-shutdown

  3. 飞书发：

    /shell ~/bin/pc-shutdown

  4. 重要机器用 /mode default + 二次确认

  5. 别把 shutdown / rm -rf / format 放自由模式
