本地电脑部署大模型

Win11整机部署方案：Ollama + Diffy 本地通义千问，实现AI操控本机电脑完整步骤

你的配置：24核32线程CPU、32G内存、12G显存N卡、1TB固态，硬件完全足够，可以跑量化版通义千问，并且让Dify接管Windows系统操作。
整体架构：
Ollama：本地跑千问大模型，提供API接口；
Dify：连接Ollama，拥有文件读写、打开软件、执行命令、操控Windows系统权限。

前期Win11系统设置（必做，否则会卡顿、调用失败）

1、开启硬件虚拟化（你已经开启，跳过检查即可）

此电脑右键→属性→高级系统设置→高级→性能设置→高级；
任务管理器→性能→CPU，查看虚拟化：已启用。

2、开启Windows开发者模式，放开系统权限（Diffy操控电脑必备）

  1. Win+i打开设置 → 隐私和安全性 → 开发者选项

  2. 勾选：开发人员模式、允许应用通过本地回路（Loopback）通信

    高级系统设置，系统变量，变量名填： OLLAMA_HOST

    变量值填： 0.0.0.0:11434

  3. 关闭Windows Defender实时保护（临时关闭，避免拦截ollama、dify程序）
    设置→隐私和安全性→Windows安全中心→病毒和威胁防护→管理设置，关闭实时保护。

  4. 管理员打开PowerShell，执行命令安装WSL：

wsl --install
wsl --update

再次重启电脑，设置完成即可。

设置WSL默认版本为2：

wsl --set-default-version 2
  1. 设置WSL默认版本为2：

powershell
wsl –set-default-version 2

3、安装必备运行库

下载微软VC++运行库合集（2015-2022 x64+x86），全部安装重启电脑，ollama缺少运行库会直接闪退。

微软官方原版 VC++2015-2022 永久直链（微软官方地址，无捆绑）

x64（64位系统必装，Win11默认64位）

https://aka.ms/vc14/vc_redist.x64.exe

x86（32位组件，ollama、diffy必须依赖，一定要装）

https://aka.ms/vc14/vc_redist.x86.exe

Windows安装Ollama（本地千问模型服务端）

Ollama作用：离线拉取通义千问模型，在后台运行，开放127.0.0.1:11434接口，给Diffy调用。

  • 步骤1：官网安装Ollama Windows版
  1. 进入ollama官网下载Windows安装包，默认一路下一步安装。
  2. 安装完成后，重启电脑。
  3. 验证安装：按下Win+R，输入cmd打开命令提示符，输入：
    ollama –version

出现版本号，说明安装成功。

  • 步骤2：配置Ollama环境变量，充分利用你的12G N卡显存（关键优化）

默认Ollama显存调用很低，必须手动配置，否则CPU满载、模型极慢。

  1. 此电脑右键属性→高级系统设置→环境变量；
  2. 系统变量新建两个参数：
    变量名： OLLAMA_GPU_OVERHEAD
    变量值： 10240
    变量名： OLLAMA_NUM_PARALLEL
    变量值： 4

作用：强制N卡占用10G左右显存，预留2G给系统，完美适配你12G独显。设置完成重启电脑。

  • 步骤3：拉取通义千问蒸馏量化模型（适配12G显存版本）

打开cmd命令行，执行拉取命令。
你的显存32G内存+12G独显，推荐两款，任选其一：

版本A（流畅首选，速度快，适合自动化操作，推荐）通义千问7B量化4bit

ollama pull qwen3:32b-q4_k_M

这个模型体积小，12G显卡完美满载，响应速度快，Diffy执行指令不会卡顿，做系统自动化首选。

等待自动下载，全程联网即可，下载完成后自动导入。

  • 步骤4：本地测试Ollama千问是否正常运行

cmd输入命令运行对话：

ollama run qwen3:32b-q4_k_M

随便输入提问，如果可以正常回复，说明Ollama部署成功。输入 /bye 退出对话。

同时测试接口连通性：
打开浏览器访问： http://127.0.0.1:11434
出现 Ollama is running 字样，接口正常，可以给Diffy连接。

补充：Ollama会开机自启，后台常驻，不用每次手动打开。

安装Docker Desktop（官方原版）

1、下载地址

Docker官网Windows AMD64安装包：
https://www.docker.com/products/docker-desktop/
文件名：Docker Desktop Installer.exe

2、安装步骤

  1. 双击安装包，配置页面必须勾选：
    ✅ Use WSL 2 instead of Hyper-V
    ✅ Add shortcut to desktop
    ✅ Add Docker to system PATH
  2. 点击Install安装，完成后重启电脑。

3、首次启动Docker配置

  1. 打开Docker Desktop，同意协议，选择Skip登录，不用注册账号。
  2. 开启WSL集成：
    设置→Resources→WSL Integration，打开Ubuntu开关，Apply & Restart。
  3. 分配内存（适配你32G大内存）：
    设置→Resources，内存调为12GB，CPU给到16核，磁盘不限，保存重启Docker 。
  4. 镜像加速（解决拉取镜像很慢问题）
    设置→Docker Engine，替换配置：
{
  "builder": {
    "gc": {
      "defaultKeepStorage": "20GB",
      "enabled": true
    }
  },
  "experimental": false,
  "features": {
    "buildkit": true
  },
  "registry-mirrors": [
    "https://hub-mirror.c.163.com/",
    "https://mirror.baidubce.com",
    "https://docker.1panel.live",
    "https://docker.mirrors.ustc.edu.cn/"
  ]
}

点击Apply & Restart。

4、验证Docker是否正常

管理员打开PowerShell，输入：

docker --version
docker compose version

输出版本号，说明安装成功。

部署Dify（Docker Compose一键部署）

方式A：Git克隆（推荐）

管理员PowerShell执行：

进入D盘新建文件夹，纯英文路径，不要中文、空格

D:
mkdir AI
cd AI
git clone https://github.com/langgenius/dify.git
cd dify/docker

方式B：没有Git，直接下载ZIP压缩包

源码地址：https://github.com/langgenius/dify/archive/refs/heads/main.zip
解压到纯英文路径，例如： D:\AI\dify-main
然后进入docker文件夹，按住Shift+右键，在此处打开Windows终端。

关键配置文件复制

终端执行：

copy .env.example .env

这个命令把默认配置复制为正式配置文件，不要跳过 。

启动Dify全部容器（一条命令）

docker compose up -d

等待3~10分钟，自动拉取全部镜像、初始化数据库 。

查看运行状态：

docker compose ps

所有服务状态显示 running 即为成功。

四、初始化Dify网页后台

浏览器打开地址：
http://localhost/install

设置管理员邮箱、密码，完成初始化，之后登录Dify工作台。

五、最重要：Dify对接你本机已经运行的Ollama（通义千问模型）

Ollama默认地址： http://host.docker.internal:11434 ，Docker容器访问本机固定写法，不能写127.0.0.1。

  1. Dify后台：模型供应商 → 添加模型 → 选择Ollama或者OpenAI
  2. 参数填写：
  • API地址(Base URL)：
    http://host.docker.internal:11434/v1
  • API密钥：任意填写，比如 ollama123 （Ollama本地无需真实密钥）
  • 模型名称，严格复制你拉取的千问名称：qwen3:32b-q4_k_M
  1. 点击保存，点击测试连接，提示连接成功即可。

至此：Docker+Dify部署完成，并且已经连上你本地Ollama跑的通义千问，全程离线本地运行。

常用运维命令（保存备用）

  1. 停止Dify全部服务
docker compose down

  1. 更新Dify版本并重启

    git pull
docker compose down
docker compose up -d --build

    查看运行日志，排查报错

docker compose logs -f

常见报错解决

  1. Docker一直卡在Starting Engine
    解决：开启虚拟化、重装WSL，执行 wsl –update 后重启电脑。
  2. Dify连接不上Ollama
    原因：Docker容器不能访问127.0.0.1，必须填写 host.docker.internal:11434 。
  3. 镜像下载速度极慢
    必须配置前面给的中科大镜像源，重启Docker。

填写Ollama连接参数

严格按照下面的内容填写，尤其注意不要加 /v1 ：

  • Base URL： http://你第一步查到的IP:11434
    示例： http://192.168.1.100:11434
    ⚠️ 重点提醒：末尾绝对不要加 /v1，这是和OpenAI兼容模式的核心区别，加了必然连接失败。
  • API Key：完全留空不填，本地Ollama不需要鉴权。

填完后点击「保存/测试连接」：

  • 提示连接成功：Dify已经能正常访问你的本地Ollama
  • 连接失败：90%是Windows防火墙拦截了11434端口，去「Windows Defender 防火墙 → 高级设置 → 入站规则」里，新建规则允许11434端口的TCP连接。

添加 qwen3:32b 模型到Dify

  1. 回到「模型供应商」页面，点击你刚添加的Ollama厂商进入详情
  2. 点击 添加模型 按钮
  3. 参数填写：- 模型类型：选择 LLM（大语言模型，对话聊天用，是唯一正确选项）
  • 模型名称：
    正常情况下Dify会自动同步你Ollama里的所有模型，下拉直接选中 qwen3:32b-q4_k_M 即可；
    如果没有自动同步，就手动严格输入，必须和 ollama list 里的名字完全一致，大小写、下划线都不能错。
  • 其余参数（上下文长度、温度等）保持默认即可，后续可以按需调整。
  1. 点击「保存」，模型添加完成。

测试验证

  1. 回到Dify工作室，新建一个空白对话应用
  2. 在「提示词编排」页面，右上角模型选择里，找到你刚添加的Ollama-qwen3模型
  3. 输入测试内容发送，能正常回复就代表全部配置成功。

OpenClaw 原生支持对接本地 Ollama

一、前置准备（必须先完成）

  1. 确保 Ollama 与千问模型就绪

  2. 启动 Ollama 服务（Windows 打开 Ollama 客户端即可，Linux/macOS 系统自动后台运行）

  3. 拉取你需要的千问模型（终端执行）：

示例：拉取千问2.5 7B模型，可根据硬件选择 qwen2.5:3b / qwen2.5:14b / qwen3:7b 等

ollama pull qwen2.5:7b

  1. 验证 Ollama 服务正常：浏览器访问 http://localhost:11434 ，页面显示 Ollama is running 即为正常。

提示：如果 OpenClaw 和 Ollama 不在同一台机器上，需要在 Ollama 设置中开启「Expose Ollama to the network」，并使用机器 IP 替代 localhost。

  1. 确认 OpenClaw 已安装

无论是桌面客户端版还是命令行版，v0.15 及以上版本均原生支持 Ollama 提供商。

二、方法一：桌面图形界面配置（新手推荐）

这是最简单的方式，直接在 OpenClaw 可视化界面操作：

  1. 打开 OpenClaw 客户端，点击右上角设置
  2. 左侧菜单选择模型配置 / Providers
  3. 在列表中找到 Ollama 选项，开启开关
  4. 在地址栏填写： http://127.0.0.1:11434
  5. API Key 随便填写即可（本地不需要真实密钥，一般填 ollama-local ）
  6. 点击「测试/拉取模型」，会自动识别出你本地已下载的所有模型（包括千问）
  7. 在「默认模型」中选择你要使用的千问模型，保存配置即可

配置完成后新建对话，系统就会调用本地 Ollama 的千问模型进行推理。

三、方法二：一键命令行启动（最快方式）

如果你使用命令行版 OpenClaw，且 Ollama 版本 ≥ v0.17.0，可以用一条命令直接完成对接并启动：

ollama launch openclaw --model qwen2.5:7b
  • 该命令会自动配置 OpenClaw 与 Ollama 的连接，自动发现本地模型
  • –model 后面替换成你本地已下载的千问模型全名（如 qwen3:14b ）
  • 启动后直接进入 OpenClaw 交互界面，全程离线可用

四、方法三：手动修改配置文件（精细控制）

适合需要自定义上下文窗口、最大输出 Token 等参数的高级用户，步骤如下：

  1. 找到配置文件
  • Windows： C:\Users\你的用户名.openclaw\openclaw.json
  • macOS/Linux： ~/.openclaw/openclaw.json
  1. 添加 Ollama 提供商配置

在配置文件的 models.providers 节点中加入以下内容（已适配千问模型参数）：

{
  "models": {
    "providers": {
      "ollama": {
        "baseUrl": "http://127.0.0.1:11434/v1",
        "apiKey": "ollama-local",
        "api": "openai-completions",
        "models": [
          {
            "id": "qwen2.5:7b",
            "name": "Qwen2.5 7B 本地",
            "reasoning": false,
            "contextWindow": 128000,
            "maxTokens": 8192,
            "cost": {
              "input": 0,
              "output": 0,
              "cacheRead": 0,
              "cacheWrite": 0
            }
          }
        ]
      }
    }
  }
}

注意： id 必须和你 Ollama 里的模型名完全一致（可通过 ollama list 查看）； contextWindow 和 maxTokens 根据你所选的千问模型规格调整。

  1. 设置为默认模型

在 agents.defaults 节点中添加，让 OpenClaw 默认使用本地千问：

{
  "agents": {
    "defaults": {
      "model": {
        "primary": "ollama/qwen2.5:7b"
      }
    }
  }
}

保存文件后重启 OpenClaw 即可生效。

五、本地模型优化建议

千问等本地开源模型的工具调用能力弱于云端大模型，建议做以下优化提升稳定性：

  1. 开启本地精简模式：在 Agent 配置中加入 experimental.localModelLean: true ，会自动减少工具数量、简化提示词，降低本地模型的处理压力。json
    {
    “agents”: {
    “defaults”: {
    “experimental”: {

     "localModelLean": true

    }
    }
    }
    }

  2. 优先选择 7B 及以上参数的千问模型，过小的参数量无法支撑 OpenClaw 的 Agent 工具调用逻辑。

  3. 如果出现命令执行异常、工具调用失败，优先升级千问模型版本（推荐 Qwen2.5 及以上），其工具调用能力有明显提升。

六、常见问题排查

  • 连接失败：确认 Ollama 已启动，端口 11434 未被占用，防火墙未拦截本地连接。
  • 模型不显示：检查配置里的模型 id 是否和 ollama list 输出的名称完全一致，区分大小写和标签。
  • 响应很慢：本地推理速度取决于你的显卡性能，NVIDIA 显卡会自动加速；纯 CPU 运行建议用 3B/7B 小参数模型。

整机性能优化设置（适配你32G内存、12G显卡配置）

1、Ollama限制内存占用设置（环境变量追加）

新增系统环境变量：
名称： OLLAMA_MAX_MEMORY
值： 20GiB
意思是最多占用20G内存，你总共有32G，剩下12G留给Windows系统和Diffy，不会内存溢出。设置完重启电脑。

2、Dify性能设置

  1. 上下文窗口长度设置为8192；
  2. 温度temperature调整为0.1（自动化执行任务，需要模型严谨，不要创意发挥，数值越低越死板听话）；
  3. 关闭联网搜索功能，全程纯本地离线运行，不消耗流量。

完整验证：测试AI操控电脑功能

在Dify对话框输入指令，测试本地千问能否操作本机：
示例指令：

  1. “查看C盘桌面所有文件名称”
  2. “打开记事本软件，写入一段文字”
  3. “查看当前电脑CPU占用率”

如果千问可以调用系统命令、执行操作，整套 Ollama+Diffy+通义千问本地部署全部完成。

六、常见故障汇总

  1. Diffy连接Ollama超时
    解决：关闭防火墙、关闭杀毒软件，开启Windows本地回路权限。
  2. 模型运行很慢，CPU占用100%
    原因：没有配置显卡环境变量，Ollama只用CPU运行，回去重新设置OLLAMA_GPU_OVERHEAD变量。
  3. Diffy无法读取磁盘文件
    原因：文件夹路径中文、权限没有全开，把Diffy解压到纯英文路径，全开系统权限。
  4. ollama拉取模型失败
    解决：cmd右键以管理员身份运行，再执行pull命令。
