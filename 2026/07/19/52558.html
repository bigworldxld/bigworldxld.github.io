app导出sqlite数据

在有 Root 权限 和 ADB 工具 的前提下，查看手机 App 的 SQLite 数据库最稳妥的方案是把数据库文件从手机拉取到电脑，再用图形化工具打开。以下是详细步骤和工具清单：

一、详细操作步骤

1. 准备与连接

  • 手机开启 USB 调试，连接电脑。
  • 电脑终端输入 adb devices，确认设备已授权列出。

2. 获取 Root 权限并定位数据库

  • 进入 Shell 并切换 Root：

    adb shell
su

    手机端需授权 Root 权限，看到提示符变为 # 或 uid=0(root) 即成功。

  • 查找目标 App 的包名（若已知可跳过）：

    adb shell pm list packages | grep 关键字

  • App 数据库默认路径为：

    例如：/data/data/com.example.app/databases/

3. 复制并拉取数据库文件到电脑

由于 /data/data/ 受 SELinux 限制，直接 adb pull 有时会失败，推荐先 复制到公共目录（如 /sdcard/）再拉取：

# 在 adb shell (root) 下执行
cp /data/data/<包名>/databases/<数据库名>.db /sdcard/
exit

然后在电脑端拉取：

adb pull /sdcard/<数据库名>.db ./

若设备支持 adb root，也可尝试直接拉取：

adb root
adb pull /data/data/<包名>/databases/<数据库名>.db ./

注意：如果 App 使用了 SQLCipher 等加密数据库，拉取出的 .db 文件需要密码才能打开，普通工具无法直接查看明文。

4. 使用电脑端工具打开

打开下文推荐的 SQLite 查看工具 → 打开数据库 → 选择刚拉取到的 .db 文件，即可浏览表结构和数据

二、电脑端 SQLite 数据库查看工具推荐

以下是常见且好用的跨平台/Windows 工具：

  • DB Browser for SQLite (DB4S)

    免费开源、跨平台（Win/macOS/Linux），界面像表格，支持浏览数据、执行 SQL、编辑记录，是最常用首选。

  • SQLiteStudio

    免费跨平台，功能比 DB4S 更偏“专业管理”，支持多数据库管理、插件、SQL 高亮与历史，适合重度使用者。

  • DBeaver Community

    通用的全能数据库管理工具（支持 SQLite / MySQL / PostgreSQL 等），社区版免费，适合本身就有多数据库管理需求的开发者。

  • SQLite Expert (Personal)

    Windows 平台老牌工具，Personal 版免费，界面偏传统但功能扎实，适合只看 SQLite 的场景。

  • 命令行 sqlite3

    电脑安装 SQLite 后，用 sqlite3 xxx.db 进入 CLI，执行 .tables、.schema、SELECT 等，适合服务器或无界面环境

三、基础操作

1. 打开数据库

sqlite3 /path/to/your/database.db

如果文件不存在，sqlite3 test.db 会新建一个空库。

2. 退出与帮助

.quit        -- 退出（或 .exit）
.help        -- 查看所有点命令(dot commands)帮助

四、查看数据库与表结构（元命令）

SQLite 中以 . 开头的叫点命令，不需要以分号结尾。

命令 作用
.databases 列出当前连接的数据库文件及对应别名
.tables 列出当前库中所有的表
.schema 显示所有表的建表 SQL
.schema 表名 查看指定表的建表语句
.indices 或 .indexes 表名 查看索引
.dump 导出整个数据库的 SQL 转储
.dump 表名 导出指定表的数据和建表语句

👉 让输出更好看

.mode column       -- 以列模式展示（类似表格）
.headers on        -- 显示列名
.nullvalue NULL    -- 把 NULL 显示为 'NULL' 而非空白
.timer on          -- 显示每条 SQL 的执行耗时

建议每次打开库后先执行这四条，观感会好很多：

.mode column
.headers on
.nullvalue 'NULL'

五、标准 SQL：查数据

1. 查全部数据（慎用大表）

SELECT * FROM user;

2. 条件查询 & 排序

SELECT id, name, age 
FROM user 
WHERE age > 18 
ORDER BY age DESC 
LIMIT 10 OFFSET 0;

3. 模糊搜索 & 计数

SELECT COUNT(*) FROM user WHERE name LIKE '%张%';

六、标准 SQL：增删改数据

⚠️ 注意：直接用命令行改生产环境的 App 数据库有风险，建议先 .backup 或提前备份原文件。

1. 插入数据（INSERT）

INSERT INTO user (name, age, email) 
VALUES ('张三', 25, 'zhangsan@example.com');

2. 更新数据（UPDATE）

UPDATE user 
SET age = 26, email = 'new@example.com' 
WHERE name = '张三';

⚠️ 切记带 WHERE 条件，否则全表字段都会被改成一样的值！

3. 删除数据（DELETE）

DELETE FROM user WHERE id = 5;

七、进阶常用技巧

1. 查看表字段详情（PRAGMA）

除了 .schema，还可以用 SQL 方式看表结构：

PRAGMA table_info(user);
-- cid|name|type|notnull|dflt_value|pk

一眼看清哪个字段是主键(pk=1)、是否允许为空。

2. 导出查询结果到 CSV

.mode csv
.output user_export.csv
SELECT * FROM user;
.output stdout     -- 切回屏幕输出

3. 导入 CSV 到表

.mode csv
.import data.csv target_table

4. 不进入交互模式，一行命令查数据

适合写脚本或配合 ADB 使用：

sqlite3 /path/to/db.db "SELECT * FROM user LIMIT 5;"

八、结合你前面场景的实用小组合

从手机拉下来 .db 文件后，快速过一遍结构的流程：

sqlite3 app.db

进入后执行：

.mode column
.headers on
.tables
.schema
SELECT * FROM sqlite_master WHERE type='table'; -- 系统表里看所有对象

⚠️ 几个容易踩的坑提醒

  1. 外键默认关闭：如果需要检查外键约束，需手动开：

    PRAGMA foreign_keys = ON;

  2. WAL 模式：很多现代 App 数据库开启了 WAL（journal_mode=WAL），直接拷出来的 .db 有时需要把同目录下的 -shm 和 -wal 文件也一起拷过来，或者先强制检查点再拷，否则可能看不到最新写入的数据。

  3. 只读打开：如果不小心动了不想动的数据，可以用只读模式打开防误改：

    sqlite3 -readonly /path/to/app.db
