入门DeepEval框架

DeepEval
tools
发布日期:   2026-07-26
文章字数:   3.1k
阅读时长:   12 分
阅读次数:  

DeepEval 是当前最主流的开源 LLM 评估框架，由 Confident AI 团队维护，采用 Apache 2.0 许可。它本质上相当于”LLM 版的 pytest”——让你用写单元测试的方式，对大模型应用的输出做量化评估、回归测试和 CI 集成。

🌐 官网与平台关系

很多人会混淆两个站点，这里一次说清：

  • DeepEval 官网：deepeval.com —— 框架本体、文档、快速开始都在这

  • Confident AI 平台：confident-ai.com —— DeepEval 背后的团队做的云端 AI 质量平台，提供测试结果集中存储、协作、观测、生产监控、人工标注等功能

两者关系是：DeepEval 负责在本地跑评估，Confident AI 负责把评估结果存到云端做团队协作。DeepEval 完全开源免费，可单独使用；Confident AI 有免费额度，团队版付费。

💡 简单记：DeepEval = 评估引擎（pip 包）；Confident AI = 评估结果的可视化与管理平台（可选接入）。

🎯 核心使用场景

DeepEval 官方覆盖了三大类应用场景，每类都有独立的 Quickstart：

1. RAG 应用评估

  • 端到端评估 RAG 流水线质量

  • 把检索器和生成器作为独立组件分别评估（检索召回的 chunk 质量 vs. 最终生成的答案质量）

  • 支持多轮 RAG 对话评估

2. AI Agent 评估

  • 端到端评估 Agent 的任务完成度

  • 借助 @observe 装饰器或框架集成（LangChain/LangGraph/OpenAI/CrewAI 等）做组件级评估：子 Agent、工具调用、LLM 调用各自打分

  • 多 Agent 系统评估

3. Chatbot / 多轮对话评估

  • 单轮 LLMTestCase 与多轮 ConversationalTestCase 双模式

  • 评估专业性、一致性、安全性等

4. 其他场景

  • 红队测试：检测毒性、偏见、SQL 注入、提示词注入等 40+ 安全漏洞

  • 模型基准测试：MMLU、HellaSwag、GSM8K 等

  • Prompt 自动优化：DeepEval 可自动优化提示词

  • CI/CD 回归测试：质量低于阈值时构建失败，防止劣质 Prompt 上线

  • 生产环境线上评估：通过 Confident AI 监控实时 trace 并跑在线评估

🧱 核心概念

理解这四个概念，就理解了 DeepEval 的运作方式：

概念 含义
Test Case（测试用例） 一次 LLM 交互单元，包含 input（用户输入）、actual_output（LLM 实际输出）、可选 expected_output（标准答案）、retrieval_context（RAG 检索到的上下文）
Metric（指标） 评分逻辑，决定输出是否满足标准。50+ 内置指标，分数 0-1，搭配 threshold 决定测试通过与否
Dataset（数据集） Golden（测试用例输入）的集合，让评估可在不同 Prompt / 模型 / 版本间重复运行
Trace（链路） Agent 运行时记录，包含每一步的 LLM 调用、工具调用、检索过程，用于组件级评估

内置指标包括：G-Eval（基于思维链的自定义评判）、Faithfulness（忠实度/反幻觉）、Answer Relevancy（答案相关性）、Contextual Recall/Precision（上下文召回/精确度）、Hallucination（幻觉）、Bias（偏见）、Toxicity（毒性）等 50+ 个

🚀 详细使用步骤

第一步：环境准备与安装

# 建议新建虚拟环境
python -m venv deepeval-env
deepeval-env\Scripts\activate

# 安装（要求 Python >= 3.9）
pip install -U deepeval

如果需要 trace 可视化调试功能，安装带 inspect 子模块的版本：

pip install -U deepeval[inspect]

📌 [inspect] 子模块会增大包体积，官方建议仅开发环境安装。

第二步：（可选）登录 Confident AI

deepeval login

按提示在 CLI 创建账户、粘贴 API Key。这一步是可选的——不登录也能在本地跑评估，但评估结果只存在本地；登录后测试结果会上传云端，可生成可分享的报告、做版本对比。

第三步：配置评估模型 API Key

DeepEval 的大多数指标（如 G-Eval、Faithfulness）需要用 LLM 当评委，因此需要配置一个评估用的 LLM：

# Windows PowerShell
$env:OPENAI_API_KEY="your-openai-key"

# Linux/Mac
export OPENAI_API_KEY="..."

也可以使用自建模型或其他供应商，详见官方文档。

第四步：写第一个评估用例

创建 test_example.py：

from deepeval import assert_test
from deepeval.test_case import LLMTestCase, SingleTurnParams
from deepeval.metrics import GEval

def test_correctness():
    # 1. 定义评估指标
    correctness_metric = GEval(
        name="Correctness",
        criteria="Determine if the 'actual output' is correct based on the 'expected output'.",
        evaluation_params=[SingleTurnParams.ACTUAL_OUTPUT, SingleTurnParams.EXPECTED_OUTPUT],
        threshold=0.5
    )
    
    # 2. 构造测试用例
    test_case = LLMTestCase(
        input="I have a persistent cough and fever. Should I be worried?",
        actual_output="A persistent cough and fever could be a viral infection or something more serious. See a doctor if symptoms worsen or don't improve in a few days.",
        expected_output="A persistent cough and fever could indicate a range of illnesses, from a mild viral infection to more serious conditions like pneumonia or COVID-19. You should seek medical attention if your symptoms worsen, persist for more than a few days, or are accompanied by difficulty breathing, chest pain, or other concerning signs."
    )
    
    # 3. 运行断言
    assert_test(test_case, [correctness_metric])

📋 RAG 场景的完整示例

以评估 RAG 客服机器人为例，更贴近真实工程：

import pytest
from deepeval import assert_test
from deepeval.dataset import Golden, EvaluationDataset
from deepeval.test_case import LLMTestCase
from deepeval.metrics import AnswerRelevancyMetric, FaithfulnessMetric
from your_app import rag_pipeline  # 返回 (answer, retrieved_chunks)

# 1. 构建数据集
dataset = EvaluationDataset(goldens=[
    Golden(input="公司年假政策是什么？"),
    Golden(input="如何申请病假？"),
])

# 2. 参数化测试
@pytest.mark.parametrize("golden", dataset.goldens)
def test_rag(golden: Golden):
    answer, retrieved_chunks = rag_pipeline(golden.input)
    test_case = LLMTestCase(
        input=golden.input,
        actual_output=answer,
        retrieval_context=retrieved_chunks,
    )
    assert_test(
        test_case=test_case,
        metrics=[AnswerRelevancyMetric(), FaithfulnessMetric()]
    )

运行：

deepeval test run test_rag.py

🤖 Agent 场景的组件级评估

Agent 评估的核心是埋点追踪。用 @observe 装饰器包裹 Agent 的顶层函数：

from deepeval import assert_test
from deepeval.dataset import Golden, EvaluationDataset
from deepeval.metrics import TaskCompletionMetric
from deepeval.tracing import observe, update_current_trace

dataset = EvaluationDataset(goldens=[
    Golden(input="What is pi rounded to 2 decimal places?")
])

@observe()
def my_ai_agent(query: str) -> str:
    answer = "Pi rounded to 2 decimal places is 3.14."
    update_current_trace(input=query, output=answer)
    return answer

@pytest.mark.parametrize("golden", dataset.goldens)
def test_llm_app(golden: Golden):
    my_ai_agent(golden.input)
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])

每一次 Agent 调用都会生成一条完整的 trace，里面按组件拆分成多个 span（LLM 调用、工具调用、检索），可以对 trace 整体打分，也可以对某个 span 单独打分。

🔄 无 pytest 的脚本式评估

如果在 Jupyter Notebook 或脚本里跑，可以用 evaluate() 函数：

from deepeval import evaluate
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.test_case import LLMTestCase

test_cases = [
    LLMTestCase(
        input="Who is the current president of the United States?",
        actual_output="Joe Biden",
        retrieval_context=["Joe Biden serves as the current president of America."]
    ),
]

metric = AnswerRelevancyMetric()
evaluate(test_cases=test_cases, metrics=[metric])

🏭 接入 CI/CD 与生产监控

CI/CD 集成：把 deepeval test run 放进 GitHub Actions 的 workflow YAML，每次 PR 自动跑评估，质量不达标则构建失败。

生产环境线上评估：通过 Confident AI 实现。给 trace 打上 metric_collection 标记：

from deepeval.tracing import observe, update_current_trace

@observe()
def ai_agent(input: str) -> str:
    output = "Your AI agent output"
    update_current_trace(metric_collection="My Online Evals")
    return output

这样生产环境的每次调用都会自动跑线上评估，并在 Confident AI 仪表盘上监控质量退化趋势、设置告警。

📌 关键注意事项

⚠️ Python 版本：DeepEval 要求 Python >= 3.9。如果你像之前装 PaddleOCR 那样用 Python 3.14，可能会遇到依赖不兼容——建议用 Python 3.11 或 3.12 的虚拟环境。

⚠️ 评估模型费用：G-Eval、Faithination 等基于 LLM 的指标会消耗 OpenAI API 额度。小额测试用 gpt-4o-mini 即可，成本很低。

⚠️ 阈值设置：所有指标分数 0-1，threshold 决定通过线。建议初期限值设宽松（如 0.5），积累基线数据后再逐步收紧。

💡 Confident AI 免费版够用：单人开发或小型团队用免费档完全够，包括测试结果云存储、报告分享、基础监控。
