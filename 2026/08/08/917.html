🛠 HDC：鸿蒙世界的”ADB”

HDC（HarmonyOS Device Connector）是华为官方的设备调试命令行工具。它的架构跟 ADB 几乎同构——由三部分组成：Client（PC 端执行的命令进程）、Server（PC 端后台进程，默认监听 8710 端口）、Daemon（设备端守护进程）。

💡 关键认知：HDC 不等于 ADB。HarmonyOS NEXT 设备上 ADB 是失效的，必须用 HDC；而老 EMUI 上 HDC 也用不了，只能用 ADB。

环境准备

  1. 从华为开发者联盟下载 HarmonyOS Command Line Tools
  2. 解压后，hdc 可执行文件位于 command-line-tools/sdk/HarmonyOS-NEXT-DB2/openharmony/toolchains/ 目录下
  3. 把该目录加入系统 PATH
  4. 手机端：设置 → 关于手机 → 连续点击版本号 7 次开启开发者模式，然后到系统和更新 → 开发者选项中打开”USB 调试”
  5. 验证：hdc -v 能看到版本号即成功

设备连接管理

hdc list targets          # 列出已连接设备，最常用
hdc -t <设备ID> shell      # 多设备时指定目标
hdc tmode port 8710        # 设备端开启TCP监听（无线调试前置）
hdc tconn 192.168.1.100:8710   # 无线连接设备
hdc tconn usb              # 切回USB连接
hdc kill                   # 杀掉hdc server（连接异常时救命）
hdc start                  # 重启hdc server
hdc checkserver            # 查看client/server版本是否匹配

⚠️ 连不上设备时检查四件事：USB 线是否支持数据传输、手机是否弹窗授权、PC 端 hdc 版本与设备端是否一致、Linux 下 /dev/bus/usb/ 权限是否为 777。

应用管理（HAP 包）

hdc install app.hap                    # 安装
hdc install -r app.hap                 # 覆盖安装
hdc install -d -r app.hap              # 允许降级+覆盖
hdc uninstall com.example.myapp        # 卸载
hdc shell bm clean -n com.example.myapp -c   # 清缓存
hdc shell bm clean -n com.example.myapp -d   # 清数据
hdc shell aa start -a EntryAbility -b com.example.myapp  # 启动Ability
hdc shell aa force-stop com.example.myapp   # 强杀应用
hdc shell aa dump -l                   # 查看当前任务栈
文件传输与日志
hdc file send ./localfile /sdcard/     # PC→设备
hdc file recv /sdcard/screenshot.png ./ # 设备→PC
hdc hilog                              # 实时日志（类似logcat）
hdc hilog -t MyApp > log.txt           # 过滤+保存
hdc bugreport                          # 一键bugreport
截屏与系统诊断
hdc shell snapshot_display -f /data/screenshot.png   # 截屏
hdc shell file recv /data/screenshot.png ./          # 拉到本地
hdc shell hidumper -s 10 -a screen                   # 屏幕信息
hdc shell hidumper -s WindowManagerService -a '-a'    # 当前窗口
hdc shell power-shell wakeup                          # 点亮屏幕
hdc shell getprop ro.product.model                    # 设备型号
hdc shell top                                        # 进程/线程
hdc shell netstat -tulnp                             # 监听端口
端口转发
hdc fport tcp:8080 tcp:8080    # 设备8080 → PC8080
hdc fport ls                   # 查看转发列表
hdc fport rm tcp:8080          # 删除指定转发

华为手机的命令行调试和 UI 自动化，要分两条线来看：Android 底包时代（EMUI/老鸿蒙）走 ADB，HarmonyOS NEXT 纯血鸿蒙走 HDC。两者命令相似但工具链完全独立，搞混就会像很多开发者一样在设备识别上卡半天。

下面分别把 HDC 工具链、常用命令、UI 自动化框架选型讲透。

🤖 HarmonyOS UI 自动化框架选型

鸿蒙的 UI 自动化有三条路线，按场景选：

路线一：@ohos.UiTest（ArkTS 原生，官方集成）

这是 HarmonyOS SDK 自带的 UI 测试框架，类似 Android 的 UiAutomator。但它要求用例用 ArkTS 写，并且要打包进被测 App 里运行。

四个核心 API 类：

  • Driver：入口类，负责控件查找、存在性检查、按键注入
  • On：描述目标控件特征（text、id、type 等）
  • Component：Driver 查找返回的控件对象，提供点击、滑动、属性查询
  • UiWindow：窗口对象，负责窗口拖动、最大化等
import { Driver, On } from '@ohos.UiTest'

const driver = await Driver.create()
const button = await driver.findComponent(On.text('确认'))
await button.click()
await driver.pressBack()  // 注入返回键

📌 适合：应用开发者在 DevEco Studio 内写单元测试和 UI 用例，跟 App 代码同源。

路线二：Hypium（Python 官方框架，推荐）

Hypium 是华为官方推出的 Python 版 UI 自动化框架，也是当前最推荐的 PC 端方案。特性：

  • 支持控件、图像、比例坐标三种定位方式
  • 支持多窗口操作、触摸/鼠标/键盘模拟输入
  • 支持多设备并行
  • 覆盖手机、平板、PC 等鸿蒙设备
  • 提供 PyCharm 插件，带控件查看和投屏辅助
  • 自动生成执行报告、记录设备日志和步骤截图
pip install hypium -U --trusted-host mirrors.huaweicloud.com \
  -i https://mirrors.huaweicloud.com/repository/pypi/simple
from hypium import Driver

driver = Driver()
driver.start_app("com.example.myapp")
driver.find_component(text="确认").click()
driver.swipe(100, 500, 100, 100)  # 滑动

💡 Hypium 底层就是走 HDC 通信，所以前面那套 HDC 环境是前置依赖

路线三：hmdriver2（轻量级 Python 库）

开源社区的轻量方案，非侵入式——不需要在设备上装 testRunner，通过 HDC 与设备通信。API 刻意对齐 Android 的 uiautomator2，方便 Android 自动化工程师平滑迁移。

pip install -U hmdriver2
# 带opencv截图/录屏功能
pip install -U "hmdriver2[opencv-python]"
from hmdriver2.driver import Driver

d = Driver()
print(d.device_info)
d.app_start("com.example.myapp")
d(text="确认").click()
d.swipe(100, 500, 100, 100)

三条路线怎么选：

  • 写单元测试、用例要和 App 一起打包 → @ohos.UiTest

  • 写独立的 Python 自动化项目、要官方支持、要完整报告 → Hypium（推荐）

  • 要快速上手、追求轻量和 uiautomator2 亲和 → hmdriver2

📱 老华为手机（EMUI/Android）的 ADB 方案

如果你的华为手机还是 EMUI 或早期鸿蒙（Android 底包），ADB 仍然是最直接的工具：

adb devices                              # 验证连接
adb exec-out screencap -p > screen.png   # 截图
adb shell input tap 500 500              # 坐标点击
adb shell input swipe 100 500 100 100 200 # 滑动
adb shell input text "Hello_World"       # 文本输入（英文/数字）
adb shell input keyevent 4               # 返回键
adb shell input keyevent 3               # Home键

⚠️ 华为 EMUI 10+ 的坑：要在**开发者选项里关闭”监控 ADB 安装应用”**，否则 adb install 会莫名失败；同时打开”仅充电模式下允许 ADB 调试”。

ADB 生态下的 UI 自动化框架选择更多：Appium、uiautomator2、Airtest（基于图像识别）、Open-AutoGLM（智谱开源的视觉大模型 Agent，同时支持 ADB 和 HDC）。

🎯 实操建议

如果你是在 HarmonyOS NEXT 真机上做 UI 自动化，我的建议路径是：

  1. 装 HDC → 配好环境变量，能 hdc list targets 看到设备
  2. 选 Hypium → 官方 Python 框架，文档齐全，支持多设备
  3. DevEco Studio 辅助 → 用其 Layout Inspector 看控件层级，方便写定位器
  4. hdc hilog 伴随 → 自动化跑起来后实时看日志定位问题

如果只是临时在手机上做点点击/输入的自动化（比如抢票、签到），hmdriver2 十行代码就能跑起来，比搭 Hypium 全套环境快得多。

HMNextAuto 是什么

它是原 hmdriver2 的”续命版”——hmdriver2 作为首款支持 HarmonyOS NEXT 的无侵入式框架，已经停维两年，Bug 没人修 。作者 ziguiway 基于其核心架构做了大量 Bug 修复和功能增强，这就是 HMNextAuto 。

核心定位：API 风格完全对齐 uiautomator2，让 Android 测试工程师零成本迁移到鸿蒙 NEXT 。

# uiautomator2 的写法
import uiautomator2 as u2
d = u2.connect()

# HMNextAuto 的写法（几乎一模一样）
from hmnextauto.driver import Driver
d = Driver()

click()、set_text()、swipe()、wait()、d(text="登录")、d.watcher("name").when(text="跳过").click() —— 这些方法名和选择器语法都和 u2 一致 。

它解决了什么痛点

鸿蒙 NEXT 不再兼容 Android 后，测试框架的选择面很窄 ：

方案 类型 优点 缺点
Hypium（华为官方） 侵入式 官方支持 需集成 SDK、API 风格独特、学习成本高
hmdriver2 非侵入式 API 类似 u2 已停维 2 年，Bug 无人修
HMNextAuto 非侵入式 API 对齐 u2、持续维护 需替换 import 路径

主要能力

除了对齐 u2 的基础 API 外，HMNextAuto 还扩展了 ：

  • XPath 支持：灵活的元素定位

  • 图像识别：基于模板匹配的视觉定位

  • 性能监控：CPU / 内存 / FPS 实时采集，可一键生成可视化报告

  • 通知栏控制：NotificationPanel 类统一管理 WiFi、蓝牙、亮度、通知消息等系统级操作

  • Shell 命令执行：底层走 hdc shell

  • 屏幕录制：支持 MP4 格式

  • 多设备管理：Wi-Fi 和 USB 连接均支持

  • Python 3.8 - 3.14 全版本兼容

快速开始

pip install -U hmnextauto
from hmnextauto.driver import Driver

d = Driver()  # 默认连接 hdc list targets 中的第一台设备
# d = Driver("ABC123456")  # 指定设备序列号

print(d.device_info)              # 设备信息
d.app_start("com.example.myapp")  # 启动应用
d(text="确认").click()            # 控件点击
d.swipe(100, 500, 100, 100)       # 滑动

💡 前置条件：和 hmdriver2 一样，必须先装好 HDC 并 hdc list targets 能看到设备，HMNextAuto 底层就是走 HDC 通信的
